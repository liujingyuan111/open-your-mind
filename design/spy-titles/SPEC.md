# 猜词回合屏 · 视觉规格 v0.1（提案）

配合 `docs/ROUND_SCREEN_SPEC.md` 与 `VISUAL_ANALYSIS.md` 使用。数值单位为 750 宽设计稿 px，即小程序 rpx，1 rpx = 375pt 屏上的 0.5pt。所有坐标都来自 `build.mjs`，改数值请改代码后重新生成，不要手改导出图。

## 1. 画布与网格

| 项 | 值 |
|---|---|
| 设计画布 | 750 × 1624（375 × 812pt 全面屏） |
| 顶部安全区 | 176：状态栏 + 微信胶囊，自定义导航时不放内容 |
| 底部安全区 | 68：Home 指示条 |
| 左右边距 | 30；纸片允许出血到 −12 / 762 |
| 基线网格 | 8 |
| 对角线语汇 | 30°，用于背景斜带和卡片斜切角；纸片本身只做 −1.6° 到 −0.9° 的手放倾斜 |

## 2. 颜色

| 角色 | HEX | 用途 |
|---|---|---|
| 墨黑 ink_black | `#1b1714` | 任务卡、规则条、操作条、图形主体、字 |
| 纸奶油 paper_cream | `#efe4c9` | 口头描述底色、答案字、指令条、猜对按钮 |
| 热色 hot_ink | `#d23a22` | 一处强调与危险：禁说、最后 10 秒 |

对比度（WCAG 相对亮度计算）：纸奶油/墨黑 14.1，暖次色/墨黑 8.2，热色/墨黑 3.7，纸奶油/热色 3.8。热色上的字和墨黑上的热色字只用于 ≥28 rpx 粗体（14pt bold，属于大字号，标准 3:1）。

## 3. 字体

- 字体：**Noto Sans SC**（SIL OFL 1.1），动态文字用 900 / 800 / 700 / 500 四档。
- **固定标签**（`src/static-labels.json` 加上模式名和规则标题）：`tools/extract_glyphs.py` 导出 wght 900 轮廓，`build.mjs` 重新切边。新增固定文字时先改 `static-labels.json`，再重新导出字形。
- **动态文字**：答案、禁说词、指令、上下文都是实时文字。答案逐字处理：字重 900/800 交替，±1.4° 旋转，±2.5% 基线漂移，每行一道墨黑刀口（粗 = max(2, 字号 × 0.026)，位于基线上方 30–38% 处）。
- **小程序加载**：系统不一定自带 Noto Sans SC，需要 `wx.loadFontFace`。全量中文字体超过 10 MB，建议按“题库 + UI 文案”的已知字符集做子集，由题库工具在出包时生成。这是本地 GPT B 的工作，这里只列需求。

## 5. 纸片规则

| 项 | 规则 |
|---|---|
| 手剪边 | `cutPolygon(points, seed)`：单刀 14–34px 直线，垂直偏移 ±1.3，角点退 2.2，长边 12% 概率有一个回剪小缺口；圆用 `cutEllipse`，每 22px 一个刻面 |
| 局部空间 | 每块纸片用固定 seed 只生成一次，之后靠 transform 移动；运行时缓存路径，禁止每帧重新生成 |
| 切缝 | 底色描边 4px 垫在纸片下（`paint-order: stroke`），可见 2px；只用于独立纸片 |
| 纸影 | 纸片路径的墨黑 24% 副本，屏幕坐标偏移 (3, 4)；纸片旋转时偏移方向不变 |
| 纸纹 | `export/paper-fibre-ink-wear.png` 512 平铺，透明，盖在所有内容最上层且不接收点击。纸片做位移动效时，该纸片自带一层纸纹随它移动 |
| 图标 | 512 栅格，显示约 200；切边、切缝、纸影参数按 512/200 放大，显示时与画面数值一致 |

## 6. 状态

| 状态 | 视觉变化（只改配置和插槽内容，不换布局） |
|---|---|
| ready | 卡片内只有任务标识和“准备”；倒计时显示总秒数；猜对/跳过置灰（墨黑 24% 纸影叠加），不可点 |
| playing | 第 1–5 帧 |
| last_call | 印章换热色并放大到 r 100，圆心不变；卡片标签换为热色“最后 10 秒”；底部操作条换热色。见第 4 帧 |
| correct_feedback | 卡片向右上沿 30° 斜线滑出，下一张从左下滑入；印章盖一枚暖次色“猜对”印片。反馈期间两键禁用 |
| skipped | 卡片向左横移滑出，不盖印；同样禁用两键 |
| round_finished | 操作条换成结算纸条（另行设计，不在本切片） |

本提案只画了 playing 和 last_call，其余为文字规则，确认方向后再出图。

## 7. 长答案

`fitAnswer()` 从大到小试字号，选第一个能放进 590×324 答案框的档位（行高 1.12），各行字数尽量均分。≤5 字且能单行放下 ≥112px 时保持单行，避免“给气球 / 打结”这类拆词。

| 字数 | 字号 × 行数 |
|---|---|
| 1–3 | 150 × 1 |
| 4 | 132 × 1 |
| 5 | 112 × 1 |
| 6–8 | 132 × 2 |
| 9–10 | 112 × 2 |
| 11–12 | 96 × 2 |
| 13–18 | 96 × 3 |
| 19–21 | 80 × 3 |
| 22–24 | 68 × 3 |
| 25–32 | 68 × 4 |

- 字号随字数单调下降，32 字时仍为 68（34pt）。
- 行首避头标点挂到上一行末尾。
- **建议的数据字段**：可选断行提示，例如 `一手按住|被风掀起的地图|一手找路`。`fitAnswer` 已支持，提示放不下时自动回退。现有题库没有这个字段，所以第 3、4 帧仍按均分断行，出现了“关 / 上”“被 / 风”这样的断法。是否加字段由 ChatGPT / GPT B 决定。

## 8. 双行 / 三行指令

- 正文 30 / 行高 44，每行 21 字（预留一格给挂行标点），最多 3 行，即 ≤63 字；建议 ≤60 字。
- 指令条高度随行数变化（1 行 126、2 行 170、3 行 214）。卡片和按钮不动，三行时底边 1282，距操作条 12 以上。
- 超过 3 行时 `build.mjs` 会报错。前端应在入库校验阶段拦截，而不是缩小字号。

## 9. 最后 10 秒与动效

- 进入 last_call 时，印章、标签和操作条同时换成热色纸片。这是换纸，不是渐变过渡：时长 120ms，旧纸片沿 30° 方向被新纸片盖住。
- 印章圆心保持 (640, 330) 不动，以满足匹配切换。
- 每秒数字只替换数字纸片，不移动印章；不用果冻弹跳，不用粒子。
- 建议同时触发 `wx.vibrateShort`，由前端决定。

## 10. 小屏与字体放大

- 宽度由 rpx 自动缩放。**高度是风险**：本稿按 1624 rpx 设计，16:9 屏（如 375×667pt）只有约 1334 rpx。
- 紧凑方案（未出图）：顶部安全区约 128，图标 150，模式名 56，印章 r 70，答案框高 260（32 字会落到 56 × 4 档），操作条高 200。按 128 + 40 + 160 + 58 + 470 + 214 + 220 估算约 1290，可以放下。操作条始终贴底部安全区，压缩只发生在卡片里。
- 系统字体放大时：答案框尺寸不变，`fitAnswer` 自动降档；正文类文字随系统放大，指令条按行数长高，必要时由卡片让出高度。

## 11. 给前端的实现提示

- 两种模式共用一棵组件树：`ContextLine / ModeMark / TimerSeal / RuleStrip / TaskCard / TwistStrip / ActionCutout`，全部从 `MODE_ASSETS.json` 取配置。
- 静态纸片（衬纸、背景道具、卡壳）可以直接用 `icons/`、`patterns/`、`masters/` 中的 SVG，或者 `export/` 中的 PNG。
- 尺寸随内容变化的纸片（指令条）在运行时调用 `src/cutpaper.mjs` 生成路径并缓存。也可以按行数预生成 1/2/3 行三种。
- 答案和指令永远是实时文字；`src/layout.mjs` 的 `fitAnswer` / `wrapTwist` 可以直接复用。
- 如果最终是小游戏（Canvas），上面的路径数据可以直接画进 `Path2D`；切缝用描边，纸影用偏移副本，纸纹用 `drawImage` 平铺。
